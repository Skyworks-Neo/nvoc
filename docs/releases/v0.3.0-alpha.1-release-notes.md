## 1. Overview

This cycle is, at its core, a **reverse-engineering cycle**. The `nvapi-rs`
submodule — NVOC's clean-room binding library for NVIDIA's undocumented NVAPI
surface — moved from the 0.1.x line to **0.3.0** on the strength of 251 commits
that re-derived, corrected, and systematized the private control plane: the
V/F plane (VFP) record model, the ClkDomains clock-record family, the ADC V2
device directories, the RM power-policy object model, and the legacy
(BIT-family) vBIOS formats.

Everything user-facing in this release stands on that foundation:

- **Per-generation correctness.** OC surfaces that previously assumed one
  layout now decode per generation — Maxwell/Kepler vBIOS ladders, Pascal's 2×
  private axes and second-cluster clock domains, Ada's EXT-slot packing,
  Blackwell's V2 record variant and plane slots.
- **A vocabulary, not a pile of commands.** The CLI adopted a strict
  `public-` / `private-` / `legacy-` taxonomy in which the command name tells
  you which NVAPI line you are driving. This is a **breaking rename** for
  existing scripts (section 8).
- **Frontends that keep up.** The GUI and TUI render the new multi-rail,
  multi-domain curves with interactive editing, and got an order-of-magnitude
  startup-memory fix (~800 MB → ~100 MB).

## 2. Architecture Innovations (nvapi-rs 0.3.0 & the RE overhaul)

### 2.1 A type-safe binding layer

- **`NvValue` type system and the `nvapi-macros` crate**: `NvStruct` /
  `NvInherit` / `VersionedStructField` proc-macros replaced hand-maintained
  struct plumbing; type-safe enums (`NvEnum`) replaced raw `u32` constants;
  a zeroed-box soundness fix and a `counted()` clamp helper hardened the FFI
  boundary.
- **Diagnostics instead of guesses**: a thread-local last-error ledger,
  stamp-gated error propagation with numeric status codes, sys-level
  `log` / `log-kv` FFI tracing, and real OS load-error passthrough (Linux /
  Windows-on-Arm) — failures now carry *why*.

### 2.2 The V/F plane (VFP) model, rebuilt

- **Per-plane, per-rail decoding**: EXT-section per-domain current slots
  (`+0x74..+0xA8`, Ada A/B packing), the current-voltage slot at `+0x68`,
  Q12 prior base, `--dump-records` raw-record slot maps, and `g(def)` priors.
- **Corrections that un-broke rendering**: the V1 VfPoints GetStatus field
  map had freq/volt shifted by +4; the VFP plane-divergence case is *legacy
  data, not corruption* — the library now returns it instead of panicking,
  and frontends synthesize an effective curve as a fallback.
- **Blackwell**: a private V/F record variant with per-point volt-offset
  fields and dedicated plane slots.

### 2.3 The ClkDomains / clock-record family

- Record-table decoding per generation, with the mask seed corrected from
  `0xFF` to `0x3FF` — bits 8/9 (Pclk0/Pclk1) are real records.
- **Empirical write labels** for Pascal / Turing / Ampere / Ada slot-0 A/B,
  replacing an alias-routing table that could not be verified.
- **TopRels GPC:XBAR ratio family + Blackwell V2 anchors** (re-RE'd off
  driver 616.92, `NvpwrControl`); the V2 record type byte is a *subtype*,
  not a pure generation stamp.
- Corrections to curve attribution: the third V/F curve was re-pinned
  HOST → SYS → **MSD**; bins #2 is DISP, not HOST.

### 2.4 Clock controllers and ADC V2

- The **ClockClkVolt controllers family** and the *nvClocks P1 batch*
  (ADC / Regimes / FreqsEnum / PubClockInfo / LockedClkMode), plus a
  `GetAllClockFrequencies` V3 compact base/boost table and
  `all_clocks_detailed` extended-domain ratio records.
- **ADC V2 directories re-reverse-engineered off R610.88** — corrected
  stamps (`0x209F0` / `0x109C8`), devices directory records starting at
  `0x70` (not `0x50`), and a 32-slot V2 fallback on status `-174`.

### 2.5 Power policy

- The **RM power-policy object model** landed on the wrapped TGP surfaces,
  giving NVOC a verified model of how power limits actually behave instead
  of a single call-and-pray write.
- Evidence-driven withdrawal: `get/set-power-mizer` was removed after RE
  showed GET is a boot-time constant and elevated SET is inert
  (`docs/reverse-engineering/nvapi/power-mizer-corevolt-pmgr-semantics.md`).

### 2.6 Legacy architectures, given the same rigor

- **BIT-family vBIOS parsing** (perf / boost / vmap / boost-ladder tables),
  Maxwell VFT decode, Pascal Virtual P-State ladder, security word +
  status string, Blackwell container, RFFS/RFRD, and fan signatures.
- Pascal: private VFP layout, second-cluster GetAllClocks domains ÷2,
  driver-dependent private-frequency scale correction, BIT token offsets
  resolved per generation.
- Volta/R391-era legacy-stamp support; legacy pstate record sub-table
  (per-ClkDomains-domain clock snapshots); Fermi legacy fan parser.

### 2.7 Audits as deliverables

The RE archive under `docs/reverse-engineering/nvapi/` grew into a citable
record: Linux version-coverage and WOA (Windows-on-Arm, arm64) coverage
audits, OC gap layouts for R610.74, an OC-surface audit, and the
power-mizer semantics memo. Conclusions are stamped with the driver and GPU
they were verified on.

## 3. Feature & Platform Support

### 3.1 GPU generation matrix

| Generation | What this release adds |
|---|---|
| **Fermi** | Legacy fan parser + legacy fan-info fallback |
| **Maxwell / Kepler** | BIT-family vBIOS ladder, `get-vbios --maxwell-vftable-decode` (GPU Boost 2.0 ladder), read-only BIOS VF ladder in GUI/TUI, `legacy-*` command family (64-slot V1 `SetClocks` stamp `0x10104`, driver-verified) |
| **Pascal** | Private VFP 2× axis decode, public defaults derived from the private table, `get-vbios --pascal-vp-decode`, private frequency-correction tag surfaced end-to-end, server/workstation paths |
| **Volta** | Server-Volta fold, R391-era legacy stamps |
| **Turing / Ampere / Ada** | ClkDomains record tables + empirical write labels, EXT-slot packing (Ada), current-voltage slot (+0x68, Ada-verified), Ampere+ coupling-boundary verdict |
| **Blackwell / RTX 50** | Generation gate + VFP raw-record transport, plane-slot routing on all ClkDomains paths, 4th (unknown) curve display, multi-rail volt-rail support (per-rail P0 blocks, status matched by rail bit), TopRels V2 anchors, GB10-tested XBAR overvolt values |

Generation detection now keys on the **codename**, never the marketing
product name — misidentification at the SKU level no longer corrupts
decoding.

### 3.2 Windows on Arm (WOA) & Linux

- WOA-aware NVAPI/NVML library selection and candidate paths; load failures
  surface the real OS error.
- Linux: `--nvapi-path` / `--nvml-path` overrides are honored on Linux;
  NVML unavailability no longer blocks NVAPI-only functionality; a
  hang-proof, **tiered** `linux_oc_recover.sh` recovery script; compatibility
  with distros that ship `python3-tk` as a system package.

### 3.3 CUDA stressor

- The cudarc binding is split into **CUDA 11 / CUDA 12 driver generations**;
  the auto-optimizer picks the right generation for the bundled stressor,
  and the build folds duplicate invocations (cuda12: 2→1, cuda11/none: 3→2).

## 4. Feature Highlights

### 4.1 CLI

- **Table-driven command metadata**: grouped, colored root help and a
  `nvoc-cli list` index; full help is shown when arguments are missing.
- New/expanded families: `get-vbios` (+ `--maxwell-vftable-decode`,
  `--pascal-vp-decode`, security word), the private V/F table suite
  (`get-private-vftable` with `--domain` / `--bank` / `--dump-records`,
  human-readable tables, per-plane slots), `pstates-2.0` dump +
  overclocked-pstates unlock, `get-power-ceiling` (the effective PPAB wall),
  `set-ecc-configuration`, `set-volt-rail-limit`, cross-certified
  clock-domain tables with FreqsEnum integration, `get-status
  all_clocks_detailed`, and legacy thermal settings.
- The CLI now runs on a **64 MiB-stack worker thread** — deep recursion in
  vBIOS parsers can no longer overflow the default stack.
- Dual-backend reads are cross-certified: NVAPI and NVML answers for the
  same domain are shown together, discrepancies are visible instead of
  silent.

### 4.2 Fan control

- New private NVAPI cooler-family surface (`query_cooler_info` in pynvoc),
  with the fan-policy verdict derived from cooler presence per generation —
  modern cards are restricted to **continuous / manual** policies, and
  fanless server cards gray out the fan pane.
- **Reset semantics fixed**: reset restores defaults *first*, then clears
  the control-block override bit (`ResetNvapiFanControl`); the NVAPI reset
  path clears the override before falling back.
- **NVML fan TDR recovery**: on device loss, NVOC shuts down the NVML
  handle globally, re-discovers, and retries — transient TDRs no longer
  wedge the fan control session.

### 4.3 Power, voltage & P-State

- `get-power-ceiling` exposes the **effective PPAB power wall** (PPAB =
  Persistent Performance Auto Boost); GUI/TUI mobile TGP sliders anchor to
  it instead of a nominal max.
- Three-tier P-State locking with priority encoded in the name:
  `pstate-lock` (admin, highest) / `private-forced-pstate-lock-user` /
  `private-permanent-pstate-lock-user` (no admin, persistent).
- Overlapping pstate locks now **warn instead of reject**, with a runtime
  pin fallback; one-sided frequency ranges render correctly.
- `set-ecc-configuration` (NvAPI `0x1CF639D9`), D-Notifier, WhisperMode 2,
  BatteryBoost 2, and per-domain private resets with plane-selector aliases.

### 4.4 Monitoring

The read-only telemetry wave (PRs #272–#292): RTSS thermal channel layout
(core / hotspot / memory temperatures), PCIe telemetry, decoded
performance-limit reasons, effective GPU clocks, NVML-sourced live power
draw, `all_clocks_detailed` per-domain ratio parents, and native Windows GPU
event queries — all rendered in expanded GUI/TUI dashboards and TUI CLK /
VOLT / TEMP lines (including video-decode clocks and multi-rail voltages).

## 9. Quality, Safety & Recovery

Overclocking writes are high-risk, and several changes target exactly that:

- Fan reset restores defaults before clearing overrides; recovery behavior
  is visible in the UI verdicts.
- `linux_oc_recover.sh` is tiered and hang-proof.
- Explicit `NvAPI_Initialize` before first enumeration fixes old-driver
  environments (#272).
- Missing limits are reported as `null`, not fabricated numbers; NVAPI init
  warnings carry the real OS error; unsupported pstate-lock overlap warns
  instead of silently rejecting.
- GPU hotplug is recovered in both frontends; identical console lines are
  collapsed so real changes stand out.
- aarch64-Linux portability: the CUDA stressor's device-enquiry buffers are
  sized as `c_char` (`u8` on AArch64 Linux, `i8` on every other release
  target) — the release matrix's only failure this cycle, now guarded by a
  cross-target check in CI and `cargo xtask ci`.

## 1. 概述

本周期本质上是一个**逆向工程周期**。`nvapi-rs` 子模块 —— NVOC 面向 NVIDIA
未文档化 NVAPI 的净室绑定库 —— 凭借 251 个提交从 0.1.x 线推进到 **0.3.0**:
重新推导、修正并体系化了私有控制面的几大支柱 —— V/F plane(VFP)记录模型、
ClkDomains 时钟记录族、ADC V2 设备目录、RM power-policy 对象模型,以及 legacy
(BIT 族)vBIOS 格式。

本版所有用户可见的改进都建立在这块地基上:

- **按代际正确解码。** 过去假设单一布局的 OC 面,现在按代际分别解码 ——
  Maxwell/Kepler 的 vBIOS 阶梯、Pascal 的 2× 私有轴与第二集群时钟域、Ada 的
  EXT-slot 打包、Blackwell 的 V2 记录变体与 plane slots。
- **一套词汇表,而不是一堆命令。** CLI 采纳严格的 `public-` / `private-` /
  `legacy-` 术语体系:命令名直接告诉你它在驱动哪条 NVAPI 线。对既有脚本这是
  **破坏性改名**(见第 8 节)。
- **前端跟得上底层。** GUI/TUI 渲染新的多 rail、多域曲线并支持交互式编辑,
  同时拿到一个数量级的启动内存优化(~800 MB → ~100 MB)。

## 2. 架构革新(nvapi-rs 0.3.0 与逆向大改)

### 2.1 类型安全绑定层

- **`NvValue` 类型系统与 `nvapi-macros` crate**:`NvStruct` / `NvInherit` /
  `VersionedStructField` 过程宏取代手工维护的结构体管道;类型安全枚举
  (`NvEnum`)取代裸 `u32` 常量;zeroed-box 合理性修复与 `counted()` 钳制
  辅助函数加固了 FFI 边界。
- **带诊断的失败**:thread-local 末次错误 ledger、stamp 门控的错误传播
  (数值状态码)、sys 级 `log` / `log-kv` FFI 追踪、真实 OS 加载错误透传
  (Linux / Windows-on-Arm)—— 失败时能回答*为什么*。

### 2.2 V/F plane(VFP)模型重建

- **逐 plane、逐 rail 解码**:EXT-section 逐域当前槽(`+0x74..+0xA8`,
  Ada A/B 打包)、`+0x68` 当前电压槽、Q12 先验基值、`--dump-records`
  原始记录槽映射、`g(def)` 先验。
- **修正了曾经"解坏渲染"的问题**:V1 VfPoints GetStatus 字段映射的
  freq/volt 曾整体偏移 +4;VFP plane 分歧情形实为 *legacy 数据而非损坏*
  —— 库不再 panic,而是原样返回,由前端合成有效曲线兜底。
- **Blackwell**:私有 V/F 记录变体,带逐点 volt-offset 字段与专用
  plane slots。

### 2.3 ClkDomains / 时钟记录族

- 按代际的记录表解码;mask seed 由 `0xFF` 修正为 `0x3FF` —— bit 8/9
  (Pclk0/Pclk1)是真实记录。
- Pascal / Turing / Ampere / Ada slot-0 A/B 的**经验写标签**,取代无法
  验证的别名路由表。
- **TopRels GPC:XBAR 比例族 + Blackwell V2 锚点**(自驱动 616.92 重逆向,
  `NvpwrControl`);V2 记录类型字节是*子类型*而非纯代际戳。
- 曲线归属修正:第三条 V/F 曲线经 HOST → SYS 重新钉定为 **MSD**;
  bins #2 是 DISP 而非 HOST。

### 2.4 时钟控制器与 ADC V2

- **ClockClkVolt 控制器族** 与 *nvClocks P1 批次*(ADC / Regimes /
  FreqsEnum / PubClockInfo / LockedClkMode),外加 `GetAllClockFrequencies`
  V3 紧凑 base/boost 表与 `all_clocks_detailed` 扩展域 ratio 记录。
- **ADC V2 目录自 R610.88 重逆向** —— 修正 stamp(`0x209F0` / `0x109C8`),
  设备目录记录起点 `0x70`(原误判 `0x50`),状态 `-174` 时回落 32 槽 V2。

### 2.5 功率策略

- **RM power-policy 对象模型**落到封装后的 TGP 面,让 NVOC 对功率限制的
  实际行为有了经过验证的模型,而不是"写一次、祈祷一次"。
- 以证据驱动的撤出:RE 证实 `get/set-power-mizer` 的 GET 是引导期常量、
  提权 SET 无效后,该命令被移除(依据存档于
  `docs/reverse-engineering/nvapi/power-mizer-corevolt-pmgr-semantics.md`)。

### 2.6 老架构同等严谨度

- **BIT 族 vBIOS 解析**(perf / boost / vmap / boost-ladder 表)、Maxwell
  VFT 解码、Pascal Virtual P-State 阶梯、security word + status string、
  Blackwell container、RFFS/RFRD、fan signatures。
- Pascal:私有 VFP 布局、第二集群 GetAllClocks 域 ÷2、随驱动变化的私有
  频率缩放修正、BIT token 偏移按代际解析。
- Volta/R391 时代 legacy stamp 支持;legacy pstate 记录子表(逐
  ClkDomains 域时钟快照);Fermi legacy 风扇解析器。

### 2.7 审计即交付物

`docs/reverse-engineering/nvapi/` 下的逆向档案长成可引用的记录:Linux
版本覆盖审计、WOA(Windows-on-Arm,arm64)覆盖审计、R610.74 的 OC gap
布局、OC 面审计,以及 power-mizer 语义备忘。结论均标注验证所用的驱动与

|---|---|
| **Fermi** | legacy 风扇解析器 + legacy 风扇信息兜底 |

### 3.2 Windows on Arm(WOA)与 Linux

- WOA 感知的 NVAPI/NVML 库选择与候选路径;加载失败透传真实 OS 错误。

  阻塞 NVAPI-only 功能;`linux_oc_recover.sh` 升级为**分层**且防挂死;
  兼容将 `python3-tk` 作为系统包发行的发行版。

### 3.3 CUDA stressor

- cudarc 绑定拆分为 **CUDA 11 / CUDA 12 双驱动代际**;auto-optimizer 为
  捆绑的 stressor 自动选择代际;构建侧合并重复调用(cuda12:2→1,
  cuda11/none:3→2)。

## 4. 功能亮点

### 4.1 CLI

- **表驱动命令元数据**:分组彩色根帮助与 `nvoc-cli list` 索引;参数缺失
  时输出完整帮助。
- 新增/扩展的命令族:`get-vbios`(+ `--maxwell-vftable-decode`、
  `--pascal-vp-decode`、security word)、私有 V/F 表套件
  (`get-private-vftable` 支持 `--domain` / `--bank` / `--dump-records`,
  人类可读表格、逐 plane 槽)、`pstates-2.0` dump + 超频 pstates 解锁、
  `get-power-ceiling`(有效 PPAB 墙)、`set-ecc-configuration`、
  `set-volt-rail-limit`、FreqsEnum 集成的交叉认证时钟域表、`get-status
  all_clocks_detailed`、legacy 温度设置。
- CLI 现运行在 **64 MiB 栈的 worker 线程**上 —— vBIOS 解析器的深递归
  不会再打爆默认栈。
- 双后端读取交叉认证:同域的 NVAPI 与 NVML 结果并列呈现,差异可见而非
  被静默吞掉。

### 4.2 风扇控制

- 新的私有 NVAPI cooler 族面(pynvoc `query_cooler_info`),风扇策略判定
  按代际从 cooler 在位情况推导 —— modern 卡仅限 **continuous / manual**
  策略,无风扇服务器卡的风扇面板整体置灰。
- **reset 语义修复**:先恢复默认,*再*清除 control-block override 位
  (`ResetNvapiFanControl`);NVAPI reset 路径在兜底前先清 override。
- **NVML 风扇 TDR 恢复**:设备丢失时全局关闭 NVML 句柄、重新枚举并重试
  —— 瞬态 TDR 不再把风扇控制会话卡死。

### 4.3 功率、电压与 P-State

- `get-power-ceiling` 暴露**有效 PPAB 功率墙**(PPAB = Persistent
  Performance Auto Boost);GUI/TUI 的移动端 TGP 滑条锚定该墙而非标称
  上限。
- 三级 P-State 锁,优先级编码在名字里:`pstate-lock`(admin,最高)/
  `private-forced-pstate-lock-user` / `private-permanent-pstate-lock-user`
  (免管理员,持久)。
- 重叠的 pstate 锁**警告而非拒绝**,附运行时 pin 兜底;单侧频率范围正确
  渲染。
- `set-ecc-configuration`(NvAPI `0x1CF639D9`)、D-Notifier、
  WhisperMode 2、BatteryBoost 2,以及带 plane-selector 别名的逐域私有
  重置。

### 4.4 监控

只读遥测浪潮(PR #272–#292):RTSS 温度通道布局(core / hotspot /
memory 温度)、PCIe 遥测、性能限制原因解码、有效频率、NVML 来源实时
功耗、`all_clocks_detailed` 逐域 ratio 父域、原生 Windows GPU 事件查询
—— 全部呈现在扩容后的 GUI/TUI 仪表盘与 TUI CLK / VOLT / TEMP 行
(含视频解码时钟与多 rail 电压)。

## 9. 质量、安全与恢复

超频写入是高风险操作,本版多处改动正对此而来:

- 风扇 reset 先恢复默认再清 override;恢复行为在 UI 判定中可见。
- `linux_oc_recover.sh` 分层且防挂死。
- 首次枚举前显式 `NvAPI_Initialize`,修复老驱动环境(#272)。
- 缺失的限制报 `null` 而非编造数字;NVAPI 初始化警告携带真实 OS 错误;
  不支持的 pstate 锁重叠警告而非静默拒绝。
- 两个前端都支持 GPU 热插拔恢复;控制台折叠重复行,让真实变化凸显。
- aarch64-Linux 可移植性:CUDA stressor 的设备查询缓冲区按 `c_char`
  定尺寸(AArch64 Linux 上为 `u8`,其余发布目标为 `i8`)—— 本周期
  发布矩阵唯一的失败点,现已由 CI 与 `cargo xtask ci` 的跨目标检查兜底。
