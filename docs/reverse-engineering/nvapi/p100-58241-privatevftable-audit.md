# P100 / GP100 @ 582.41 私有 VfTable (ClockClkVfPoints) 结构审计

日期：2026-09-30。分支 `P100-58241-privatevftable-reversing`。
诱因：P100 bank0 index 15..30 负值范围写（-100000 kHz ×2 轴 = -200000 raw）导致电压塌陷崩卡 + SetControl 楔死（-1），读回 offset 列显示 +2147383.6。

## 1. 判读快报（先读这个）

| 现象 | 判定 |
|---|---|
| 读回 +2147383.6 | **我们解码侧 bug**：`u32(-200000)/2000 = 2147383.648`。mode-0 VALUE 是 i32 kHz（二补数落表），读回按 u32 显示。已修（cli `mode0_offset_effect_mhz`）。 |
| 0..79 写 offset → 电压平移 | 与 08-30 台账"GPC 写只动电压不动请求上限"一致；单位待黑盒 E1 实证（假设 µV，2x 轴适用性待证）。 |
| 80..159 写 offset → 频率平移 | 与 08-30 A/B"MEM domain offset 命中 80..159 且真实移动 MEM 时钟"一致（233600↔+116.8MHz，因子 2000）。 |

## 3. 用户态控制记录（stride 1060B，稀疏填充是设计而非遗漏）

用户态 1060B 记录只有 4 个活字段，其余是版本翻译器留的零填充——**不存在"漏解码的隐藏字段"**，真实内容在内核内部表（见 §5）：

| 偏移 | 字段 | 说明 |
|---|---|---|
| rec+0 | TYPE（byte 生效） | **用户类型**，经翻译器映射为线上类型 |
| rec+36 | MODE（dword） | type 变体 A：0=绝对 VALUE / 1=delta i16；type 变体 B：整个 dword 就是 payload |
| rec+56 | VALUE（dword/word） | 变体 A 的 payload；**i32 kHz（负值二补数）** |
| rec+96 | FLAG（byte） | **只有 bank1 记录会被拷贝**（bank0 循环不碰它） |
| 头 +260 | 全局字节 | ↔ RM 缓冲 +316 双向回显，用途未定（GET/SET 都搬运；值得在探针里观察写行为下是否变化） |

缓冲布局：mask bank0 @+4、记录 @772（stride 1060）、mask bank1 @+2171652、记录 @2172420（stride 1060）。

## 4. 用户↔线上类型翻译器（582.41，pack=sub_1801EB5D0 / unpack=sub_1801EB2C0）

```
user→wire: 0→2  1→3  2→1  3→5  4→7  5→4  6→8  7→10  8→12  9→9  10→13  11→14  12→15  13→17  14→18  其他→-1
wire→user: 完全互逆（1→2  2→0  3→1  4→5  5→3  7→4  8→6  9→9  A→7  C→8  D→10  E→11  F→12  11→13  12→14）
```

- bank0 合法 user 类型 {0,1,3,4,7,8,12,13}；bank1 合法 {6,10,14}（wire {8,0xD,0x12}）。越界 = **-103**。
- wire {2,5,0xA,0xF}（user 0/3/7/12）：**payload = MODE dword**（单 u32 变体）。
- wire {3,7,0xC,0x11}（user 1/4/8/13）：MODE 0 → RM rec+8 = VALUE dword；MODE 1 → RM rec+8 = VALUE 低 i16。
- **我们写的 bank0 user type 8 → wire 0xC → mode/value 变体** ✓（sys 注释正确；注意 `set_record_type(8)` 会改写目标记录的变体——如果线上原类型不是 8，写入即在改变记录形态，探针 E0 必须先记录 GET 侧原类型）。
- GetStatus 家族的 type 0/1（bins/curve）是**另一套编号**，与 Control 的 user/wire 类型互不相干。

## 5. RM 侧记录与内核路径（nvlddmkm_58241.sys，与 DriverStore 逐字节一致）

RM 请求缓冲：+44=状态回填（经 `sub_18006A710` 映射为 NVAPI 返回，-1 楔死即此处产物）、+48=hGpu、+52=子命令、+60=mask bank0、**+320=bank0 记录（16B/条）**、+33092=mask bank1、**+33348=bank1 记录（16B/条）**。

RM 16B 记录：`type@+0 / mode@+4 / value@+8 / flag@+12`。

内核命令描述符表（.rdata，32B/项：`{cmd, flags, link=0x140EE3B70, handler, 0x44}`）：

| cmd | flags | handler |
|---|---|---|
| 0x2080D024 (VFP SET) | 0x1020C | **0x14057F570** |
| 0x20809023 (VFP GET) | 0x1020C | **0x14057F340** |
| 0x2080D020/1C/28 | — | 0x140579980 / 0x140578640 / 0x140584020 |
| 0x20809022/25 | — | 0x1405796C0 / 0x14057F460 |

PERF 侧发现：
- VFP 表双后端，构造时二选一（`sub_140367BA0`）：默认 8872B（方法表 +840=0x140832DA0、+848=0x140832D20、+856=0x1408318A0、+896/904=0x140832C40/C30）与客户端变体 1136B（方法 0x140833C10，版本字节 4）。选择开关 = PERF 对象 +857/858/859。
- **`RmVFPointCheckIgnore` 注册表键**（串 @0x140D62980 → `sub_140367BA0` 写对象 +875）：VF 点校验旁路开关。⚠️ 实验机严禁设置——它拆掉的是安全栏。
- `RmPerfChangeSeqOverride` 同路径出现（+8/9 子命令）。

## 6. 段语义现状与疑点

- 段标签（gpc/mem/pstate_bins）由 `nvapi-rs/src/gpu.rs segment_vf_points` 动态推导（频率单调主轴 + Pascal-HBM 80+80 结构规则），非硬编码。
- 0..79 电压语义 / 80..159 频率语义的显式对偶是本轮新知识（此前只有半条："GPC 写只动电压"）。
- **待裁决矛盾**：08-30 记录"GPC 正向 offset → 同频降压 ~50mV"（曲线频率上移特征）vs 本轮"电压上升"。E1 单点微写入 + 电压/时钟双观测裁决。
- **电压读数分层（用户实机观测，2026-09-30 修正）**：GPC 正 offset 后 **rail0 与 rail1 都真实移动**（VoltRails = 物理真值），而 get-status 里的 "VFP voltage" 不动——它是**表派生量**（疑似曲线索引/位置而非物理 µV），GPU-Z 类工具读的是后者，所以不反映偏置。修正早先"rail0-only 可见性"假设：这不是轨可见性问题，是遥测/表派生两层报告的分叉。
- MEM 段 F_def 与 GPC 阶梯 identical：GET 读回的 freq_default 是 RM 外推镜像（plateau 整段抬升已实证），**不可当生效判据**；生效判据 = VoltRails 电压 + 实测时钟。
- pstate_bins 160..167 成对值（405/405/648/648/810/810/1080/1080）与 vBIOS 'C' 表 pstate-class 值吻合（405/648/810/1080），成对结构 = 每级两份记录，语义未定。

## 6c. E1-E5 第一轮实测判读（2026-09-30，单点 #30，锁 750 mV，操作者：用户）

⚠️ 操作二进制为旧版 nvoc-cli：单点路径未做 2x 放大（raw=输入原值，E0 探针 raw dump 铁证 `value_u32=50000`），显示 bug 仍在（+2147458.6 = u32(-50000)/2000）——**这反而提供了裸 raw→物理效应的直接标定**。

| 步骤 | 表内 raw | rail0 | rail1 | 实测时钟 | 判读 |

| 基线（锁 750mV） | 0 | 762.5 mV | 762.5 mV | 1215 MHz | stock #30 = 1215@750 ✓ |
| +50000 | 50000 | 775 (+12.5) | 800 (+37.5) | 1252 MHz | 双轨均值 +25 mV = **raw/2 µV**；时钟 1252 = 硅片 stock 曲线 @775 mV |

| range 25..35 @-25000 | — | 崩卡 | 崩卡 | — | 范围负写绕过钳制 → 过欠压崩溃；**设备管理器禁用/启用成功恢复**（无需重启，恢复阶梯实测有效） |

**统一模型 v2（2026-09-30 操作者定稿；基线=锁具目标 750 mV，y=表内 raw 值）**：
1. **写入语义：rail0（GPC 核心轨）+= y/2 µV，rail1（HBM 轨）+= y µV**——双轨双增益，正向全命中：+50000 → rail0 775（750+25）✓ rail1 800（750+50）✓；+100000 → 800/843.75（预测 800/850，rail1 差一格量化）✓。
2. "Pascal ×2 进表"是补偿编码：typed ×2 = raw；raw/2 = rail0 的 µV 数。**GPC mode-0 VALUE = 点电压偏移**（µV 域， rail0 增益 ½、rail1 增益 1）——"0..79 电压语义"实锤，且 P100 双轨由同一 GPC 点偏移驱动、增益 1:2。
3. **施加后的时钟沿硅片 stock V/F 曲线走**：点电压被抬高 → 物理轨升压供电 → 实测时钟 = 新电压在 stock 曲线上对应的频率（775 mV → 1252，800 mV → 1308）。读回 freq_default 的 raw/2000 "MHz" 是镜像 artifact，**数值上与 raw/2000 mV 相同——08-30 "129300↔64.65 MHz" 标定的真正身份 = 64.65 mV 电压偏移的镜像错读**。旧"mode-0 raw = 2×真实 kHz"学说整体为单位误读。
4. **单点负向：表内全值保留、实际施加被 RM 钳到 ≈1 个 DVFS 量化步**（预测 -25/-50 → 实测双轨对称 -6.25 mV，两轨同步走一格）；**范围负写绕过该钳** → 全幅过欠压 → 崩卡（事故机理闭环；设备管理器禁用/启用实测足够恢复）。
5. **新二进制行为确认**（typed -25000 → Value -50000 → Retained 4294917296=u32(-50000)）：2x 补偿生效、负值显示修复生效（5de1411）。CLI 的 "Unit: MHz" 标签与 2x 放大按新模型需改为 µV 语义（待 MEM 段复测后单独 commit）。
6. rail1 = HBM 轨的定位使 80..159 "mem" 段与 pstate_bins 成对结构（每级两份=GPC/HBM 各一）重新自洽；MEM 段单点（#110）复测待做。08-30 "同频降压"判决与新模式表面冲突，历史调和挂起（以受控单点数据为准）。

## 6d. 死因精化（第二轮隔离实验，2026-09-30，操作者）

**v3 定稿（操作者假说，VMIN 推定被否）**：29、30 同值 raw −25000 存活；29 raw −25000 + 30 raw −50000（typed −12500/−25000）→ 软挂死，**且电压没有明显降低**——排除电气欠压，定性为**非单增 VF 表软挂死**：驱动对 raw 路径不做负向规范化，GPU 收到局部反向的表后 DVFS 引擎无法处理。

**定量法则：相邻点 raw 差分 ≥ 25000 = 恰好抵消/反转一个 stock 阶梯步（12.5 mV）**。验算（rail1 增益 = y µV，stock V30−V29 = +12.5 mV）：等值 −25000/−25000 → 差分 0 → 斜率 +12.5 单增 ✓ 活；−25000/−50000 → 差分 −25000 → 斜率 −12.5 反向 ✗ 死；单点 −50000 → 表内反向但锥钳把施加压回合法斜率 → 活。偏移量子与阶梯步长同量纲是该失效模式的结构根源。

**事故统一**：16 点等值平台 −200000 的两端边界边差分 = −200000 = 16 个阶梯步 → 边界即非法斜率，无需内部 VMIN。两种死形态区分：**表非法 = 软挂死（电压不动、-1 楔死、禁用/启用恢复）**；真欠压 = 电气硬死（电压可见下跌）——本轮所有观测均属前者。

**安全法则（v3）**：0..79 负值的安全条件 = **相邻点 raw 差分保持在 (−25000, +∞) 且绝对深度经锥钳后仍在轨窗口内**；等值平台（严格等值）局部合法但边界边差分随深度放大——深平台边界同样致命。逐点补写相邻点极易无意制造差分（#29 补写教训）。

**判决性预测（v3）**：①✅**已确认（2026-09-30）**：浅深度同差分对 typed −6250/−18750（raw −12500/−37500，差分 −25000）→ 立即死亡——差分定律与绝对深度无关，实证定案；②相邻差分 ≤ 0（高点不比低点更负）→ 活（等值对已间接证实）；③挂死前 GET 读回 freq 镜像仍单增（镜像合法而 GPU 挂 = 故障点在 GPU 表处理，非 RM 校验）（待做，低优先级）。

## 6f. 第四轮：双平面配对写 = 真实频率轴平移（2026-09-30，操作者，结构性突破）

**实验**：25-35 与 105-115（index+80 严格对应）各 typed 100000（×2 → raw 200000）→ **真实 +100 MHz @ 恒定 750 mV 锁（1328 MHz 稳定运行）**。单段写从未达成——08-30 "GPC 写只动电压不动请求上限"判决被配对写推翻：请求频率真实移动了。

**操作者模型**：0..79 = 沿曲线上行加电压（A 平面/电压侧）；80..159 正值 = 降压/频率侧（B 平面）；等值配对 = A 的电压抬升被转换为等压频率上移（净效果 = 纯频率轴平移）。次序：必须先 A 后 B。

**bank0 最终结构**：**80 点 × 双平面**（A=0..79，B=80..159，index+80 对应）。全部旧观测收敛：双段阶梯 identical、pstate_bins 成对、单 A 写只动电压（§6c）、单 B 写半更新诡异行为与窄容限（§6e）、等值配对 = 相干点重定义。

**致命条件（跨平面差分）**：B > A + 1 bin（raw 25000 = 显示 12.5）→ 暴死。**本次禁用/启用无效、需重启**（事件查看器 RM 错误风暴 0001d5a5/0001d9a0/0001d97a/0001d964/0001d8ff/0001d8f9/00000011）——配对系统差分违例的楔死深于单段违例，恢复阶梯需多一级。

**下一战场（08-30 终极问题）**：1328 是曲线顶还是硬天花板？判决实验 = 等值升级（125000/125000 → 150000/150000…）：服务频率突破 1328 = 天花板攻破；仍钳 1328 = 天花板独立于曲线（再试段宽扩展/平台段）。铁律：两平面绝对同值、先 A 后 B、-1 即停、预留重启。

**定性与工程化（2026-09-30 晚，操作者）**：
1. **所有"暴死"都是驱动把 RM 表炸烂的软挂死，不是电气事件**——轻度降压出现时序不稳定根本不会炸卡（真电气地板的形态是 ECC 不可纠正：shunt 后实测 675 mV 出现 ECC 爆炸，700 mV 时 output Vdd 峰值 395 W/平均 335 W，硅片体质 ≈ 消费级 Pascal 的 700 mV/1328 MHz，余量巨大）。工程含义：配对写控制器的价值 = 防驱动自己写烂表，而非防硬件损坏。
2. **reset 时序致命性**：reset 的本质是按序写 0（无私有 VF 表还原专用接口），按 index 顺序清零在双平面卡上致命——A[n] 先归零而 B[n+80] 仍持正值 = B > A 违例。所有 reset 路径（CLI/GUI/TUI）已改为有序配对复位（B 平面先归零、A 平面随后），核心 = 配对控制器 target 0；`--unsafe` 保留旧路径。
3. **CLI 默认配对**：set-private-vftable-{point,range}-offset 在 Server Pascal 双平面卡上默认走配对写（升先 A 后 B、降先 B 后 A，含负值）；`--unsafe` 单平面 + pairing_warning。GUI/TUI 合成单曲线，全部 apply/reset 经配对通道。

## 6e. 第三轮：80..159 段性质改判 + 单点凸包死法（2026-09-30，操作者）

**结构改判（操作者确认）：80..159 不是 mem，是 GPC 侧另一组未知功能**。bank0 图景更新：0..79 = rail0/GPC 主曲线（mode-0 偏移双轨 1:2 联动）、80..159 = GPC 侧从属组（候选：Gpc2 从属域 / 互联域 / rail1 曲线）、160..167 = 成对 bins。08-30 "MEM A/B 命中 80..159 且 mem 时钟移动"的归因待重审（观测量可能是 Xbar/Gpc2 侧误读）。

**单点 #110 凸包实验**：typed +50000（raw 100000，显示 +50）存活；typed +75000（raw 150000，显示 +75）→ 死（另一种挂死行为）。**关键对照：08-30 #103-116 十四点等值 +116.8 平台存活** → 非幅值问题，**是形状问题（与 GPC v3 同构）**：单点凸包要求曲线在凸包后回落全部偏移量，回落沿即负差分边；+75 的回落沿越过该段差分容限，+50 未越；宽等值平台无局部回落沿故存活。读回镜像两侧都被钳在 ~50 MHz/点且单增——非法性 again 只在施加态。

**软原因排序**：①从属域时钟偏斜（Gpc2/互联域对主域偏离容限小，+75 越界；08-30 "+9 MHz 泄露"与"互联域裕量小"台账支持）；②rail1 电压语义（+100/+150 mV 越 HBM/MSVDD 窄窗）；③平台拖尾长度（弱）。**判别实验**：+50 存活窗口内抓双轨电压 + 全域时钟（rail1 动=②；rail1 不动而 Gpc2 动=①）；+60/+65 二分找精确边界。

**该段安全包络（经验）**：单点 ≤ 显示 +50（raw 100000）存活；宽等值平台历史存活至 +116.8；单点凸包 ≥ +75 致死。

## 9. 适用范围（2026-09-30 操作者问询定案）

- **实锤仅 P100/GP100**（唯一深入过的 HBM 卡）：双轨 1:2 增益电压语义（§6c）、80..159 镜像段、成对 pstate_bins、偏移量子与 12.5 mV 阶梯步同量纲。
- **机制上应当跨代、未实测**：差分软挂死。陷阱在接口设计而非硅片——用户态 pack/unpack 无校验（全代共用 handler 设计）+ GPU 侧 DVFS 消费 raw 表。其他卡"没出现" ≠ 不存在：mode-0 负向差分写是本轮在 P100 上首次系统性执行，历史负向研究全走 mode-1（另一套保护）；消费级无 80..159 第二段故无镜像混淆面。
- **消费级 Pascal**：同 RM 族、同 2x 读回编码（1080 交叉验证）、同阶梯步长、单轨——差分陷阱三要素齐备，原则上同样会挂，仅从未被喂过。
- **mode-0 支持度按代分化**：V100 legacy 路径写入 inert（538.78）、CMP 170HX mode-0 不支持、P100 = 电压语义——"按代外推安全"不成立。
- **实操**：差分定律按 raw 接口通用属性对待；CLI 负向差分校验按通用实现（有第二段的卡还需考虑 80..159 镜像联动）。
